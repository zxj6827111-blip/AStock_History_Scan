## 3. 切换到 8737（二选一）

### 方案 A（推荐）：直接以发布候选目录启动 8737

优点：不覆盖运行目录，回滚只需切回旧代码；缺点：运行位置与旧目录不同，需同步启动脚本。

```bash
# 3A.1 记录旧 PID
OLD_PID=$(lsof -nP -iTCP:8737 -sTCP:LISTEN -t)
echo "OLD_PID=$OLD_PID"

# 3A.2 优雅停止旧服务
kill "$OLD_PID"
for i in {1..20}; do lsof -nP -iTCP:8737 -sTCP:LISTEN >/dev/null || break; sleep 0.5; done
lsof -nP -iTCP:8737 -sTCP:LISTEN && echo "端口仍被占用，停止发布" && exit 1

# 3A.3 启动新版
cd ".../bazi_month_relation_tengod_dev_v1/app"
nohup python3 -u server.py --port 8737 --no-browser > ../evidence/prod_8737.log 2>&1 &

# 3A.4 健康检查
sleep 2
curl --noproxy '*' -s 'http://127.0.0.1:8737/api/meta?dataset=ashare' | head -c 300
curl --noproxy '*' -s 'http://127.0.0.1:8737/api/ten_god_stats?id=510050.SH&dataset=etf'
```

### 方案 B：把代码复制进原运行目录

优点：保持原目录与 `.command` 习惯；缺点：会覆盖运行目录代码，必须先完成 1.3 备份。

```bash
cd ".../bazi_month_relation_local_v1"
cp -a app app.bak.$STAMP           # 二次备份
cp -a ".../bazi_month_relation_tengod_dev_v1/app/api.py" app/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/server.py" app/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/ten_god_rules.py" app/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/ten_god_service.py" app/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/config.py" app/
mkdir -p app/rules && cp -a ".../bazi_month_relation_tengod_dev_v1/app/rules/"* app/rules/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/static/index.html" app/static/
cp -a ".../bazi_month_relation_tengod_dev_v1/app/static/app.js" app/static/
# 不改动 database/、work/、reports/
```

然后按 3A.2 / 3A.3 重启（启动目录改为原运行目录）。

> 方案 B 的 `config.py` 默认路径指向原两库，复制后无需改路径。
> 若原目录仍有 `app/api.py` 的相对路径逻辑被其他脚本引用，先确认无其他调用方。

## 4. `.command` 启动脚本的端口一致性

原脚本：

```zsh
DIR="$(cd "$(dirname "$0")" && pwd)"
cd "$DIR/app" && exec "$PY" -u server.py
```

`server.py` 默认 `--port 0`（自动空闲端口），因此双击不保证落在 8737。

发布时二选一：

- **固定端口**：改为 `exec "$PY" -u server.py --port 8737 --no-browser`；
- **保留自动端口**：在脚本文本与文档中明确“双击是自动端口，8737 是手动固定入口”。

不要同时保留两种未说明的行为。

## 6. 回滚

### 触发条件

- 8737 无法启动或页面 500；
- 黄金案例不一致；
- 旧接口出现字段缺失/改值；
- 原库哈希变化（立即停止，不再写任何文件）。

### 回滚步骤（方案 A）

```bash
# 6A.1 停止新版
NEW_PID=$(lsof -nP -iTCP:8737 -sTCP:LISTEN -t)
kill "$NEW_PID"; sleep 2

# 6A.2 从备份目录启动旧版
cd "/Volumes/workSSD/software development/AStock_History_Scan/_release_backup_$STAMP/app"
nohup python3 -u server.py --port 8737 --no-browser > /tmp/rollback_8737.log 2>&1 &

# 6A.3 验证
sleep 2
curl --noproxy '*' -s 'http://127.0.0.1:8737/api/stock?id=510050.SH&dataset=etf' | head -c 200
```

### 回滚步骤（方案 B）

```bash
cd ".../bazi_month_relation_local_v1"
rm -rf app            # 仅在已确认 app.bak.$STAMP 完整时执行
mv app.bak.$STAMP app
cd app && nohup python3 -u server.py --port 8737 --no-browser > /tmp/rollback_8737.log 2>&1 &
```

### 回滚纪律

- **不回滚、不覆盖、不删除任何 SQLite / 行情文件**；数据库本来就没有被修改。
- 回滚只动代码与服务进程。
- 回滚后重新核对两库 SHA-256；若与发布前不一致，按 STOP-1 保留现场并报告。
- 回滚完成后保留 `_release_backup_$STAMP` 与发布日志，不立即清理。
