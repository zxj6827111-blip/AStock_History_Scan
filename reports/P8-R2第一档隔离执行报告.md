## 3. 门禁强化：不再依赖手动环境变量

R1 的设计是 `P8R1_VERIFIED=1 bash p8r1_archive.sh`——**你手滑敲一次就能绕过**。本轮改成三重绑定，全部由 `p8r2_tool.py` 内部强制：

| 机制 | 实现 |
|---|---|
| 归档器**自己跑完整验证** | `archive` 在动第一个文件前，对 511 条逐条重算 `存在 + 字节 + SHA-256`；任一条不符 → 拒绝，不产生任何移动 |
| 门禁结论与范围**密码学绑定** | `precheck` 把 `scope_sha256`（511 条 `路径+字节+哈希` 的规范序列化摘要）写进 `gate.json`；`archive` 重算当前范围摘要，不一致即拒绝。N2 实测：范围少 1 条就拒绝 |
| 新鲜度约束 | 门禁记录超过 **30 分钟**即失效（N3 实测：120 分钟 → 拒绝）。移动前必须是刚刚验过的状态 |
| 半执行防护 | 隔离目录已存在且非空 → 拒绝（N4 实测：塞 1 个探针文件即拒绝），杜绝两次执行叠加 |
| 移动瞬间二次校验 | 每条 `rename` **前**再算一次哈希；落地后立刻对隔离侧验 `字节 + 哈希 + 同卷 st_dev` |
| 失败即自动回滚 | `try/except` 包住整条循环，任何异常立刻把已移动的按逆序 `rename` 还原，并打印回滚计数 |
| manifest 逐条落盘 | 每移动 1 个文件就重写 `manifest.json`（崩溃也只丢最后一条记录，不会丢文件） |

`gate.json` 最终记录：`verdict=PASS`，24 项，`scope_sha256=9ba738fe7cbf8306…`，`ran_utc=2026-10-20T04:44:35Z`。

## 7. 我自己这轮抓到并修掉的 5 个缺陷（都不涉及业务数据）

1. **门控路径未加引号 → 假通过**。`git -C /Volumes/workSSD/software development/…` 含空格未 quote，git 报错、stdout 为空，我的 `all(… for l in [])` **恒为 True**，G4b 是假 PASS。是同批的 G4c（标签数=3）失败才暴露它。修法：`shlex.quote` + 空输出即判失败。
2. **断言口径错**：G6g 我把 `os.listdir` 的 4 个顶层条目当成「10 个文件」。已改成 `os.walk` 递归计数，与 P8 口径一致（实测 10）。
3. **A7 恒 FAIL**：比较集用的是相对项目根的 `relpath`，而 manifest 键是相对隔离区的裸路径，两个集合永不相交。修正后先塞 `__probe_decoy` 证明它变 BAD、删除后恢复 OK——**双向都验**才算断言有效。
4. **HTTP 200 不是健康信号**：该服务对未知路由也回 `200 + {"error":"未知接口"}`，我原先两条 `curl -w %{http_code}` 门禁属于弱断言。已替换为**载荷级** 29 端点逐字段比对 + 首页字节数与标识断言（S15/B5、B6）。
5. **我漏传 `--target`**：`api_compat_check.py` 的默认 target 是开发端口 **8848**，我按发布证据名以为是 8737，一度收到「29 端点全 FAIL / Connection refused」并怀疑服务被打挂。实测澄清：PID 32360 始终存活、socket inode 未变（`0x7e832062c9839e0c`）、日志无崩溃、同一时刻 curl 与禁用代理的 urllib 都拿得到真实载荷（`/api/catalog?dataset=etf` 3,084 B JSON）。**是我调用错，不是服务故障，也与移动无关**。另外顺带排除了一种常见误判：macOS 系统代理 `127.0.0.1:7897` 会被 Python `getproxies()` 继承，但该工具已用 `ProxyHandler({})` 关代理，故与此无关。

这 5 条都属「校验装置本身不可信」，比业务错误更危险；已全部落进工具与报告，下一轮直接继承。
