## 1. 本版修正的 5 个风险

| # | 原风险 | 修正 | 实测 |
|---|---|---|---|
| 1 | 方案 A 从备份目录启动旧代码，`api.py` 的相对库路径指向备份目录下不存在的 `database/`，回滚必失败 | 回滚改为**从保留不动的原运行目录 `$OLD/app` 启动**；备份只用于代码取证，不用于启动 | 已在 8851 启动旧版并返回 200 |
| 2 | 升级后仍用同一个 8737 当 OLD 和 NEW，兼容测试恒为 0 差异 | 升级前抓取 29 项快照；升级后与快照逐字段比对 | 候选 8848：29/0；旧版 8851：29/0 |
| 3 | 端口被占用时抛原始 traceback | `server.py` 捕获 `OSError`，打印中文原因并以退出码 1 结束 | 8852 占用测试：`启动失败：无法绑定 127.0.0.1:8852…`，exit=1 |
| 4 | 数据库缺失时可能带病启动 | 启动前检查两库存在/可读；缺失即 `SystemExit` | 故意指向不存在路径：exit=1，无监听 |
| 5 | 原 `.command` 不传端口，双击不保证 8737 | 新增 `$DEV/启动十神版.command`，默认 `--port 8737`，可用 `BAZI_PORT` 演练 | 8854 实测 HTTP 200、十神统计 260 |

## 5. 回滚（任一健康检查失败即执行）

### 5.1 停止新版

```bash
kill "$(cat "$DEV/evidence/prod_8737.pid")" 2>/dev/null || \
  kill "$(lsof -nP -iTCP:8737 -sTCP:LISTEN -t)" 2>/dev/null
for i in {1..20}; do
  lsof -nP -iTCP:8737 -sTCP:LISTEN >/dev/null || break
  sleep 0.5
done
lsof -nP -iTCP:8737 -sTCP:LISTEN && { echo "端口未释放，人工处理"; exit 1; }
```

### 5.2 从原运行目录启动旧版（不是备份目录）

```bash
cd "$OLD/app"
nohup /opt/homebrew/bin/python3 -B -u server.py --port 8737 --no-browser \
  > /tmp/rollback_8737.log 2>&1 &
echo $! > /tmp/rollback_8737.pid
sleep 2
curl --noproxy '*' -s -o /dev/null -w "rollback_index=%{http_code}\n" http://127.0.0.1:8737/
```

`-B` 用于避免向原目录写 `.pyc`。

### 5.3 恢复启动器

```bash

      "$OLD/启动八字历史规律查询.command"
```

## 6. 启动失败矩阵

| 场景 | 现象 | 处理 |
|---|---|---|
| 8737 被占用 | `启动失败：无法绑定 127.0.0.1:8737（[Errno 48]…）`，exit=1 | 不启动第二实例；查 `lsof`，确认旧/新进程；按第 5 节回滚 |
| 数据库缺失/不可读 | `启动中止：A股数据库不存在…`，exit=1 | 检查 `config.py` 与环境变量；不得改库；恢复原配置后重试 |
| 新服务启动但 API 500 | `/api/meta` 非 200 | 看 `prod_8737.log`；立即回滚 |
| 兼容对照非 0 | `TOTAL_DIFFS>0` | 立即回滚；保留 `api_compat_post_release.json` |
| 页面正常但旧字段变了 | 兼容报告已拦截 | 以报告为准，不以目测为准 |
| 回滚启动失败 | 旧版 200 不通过 | 检查端口是否释放、`$OLD/app` 是否被改动；备份仅用于比对，不用于启动 |
